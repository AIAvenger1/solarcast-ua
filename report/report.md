# 1. Суть проєкту та де його можна використовувати

SolarCast UA — вебсервіс, який прогнозує, скільки електроенергії дасть домашня
сонячна станція найближчі сім днів, і підказує, коли цю енергію найвигідніше
використати.

Власник панелей з акумулятором або зарядною станцією щоранку відповідає на три
запитання: чи вистачить сонця зарядити акумулятор до вечора, коли вмикати пральну
машину чи бойлер, і в які дні розраховувати лише на мережу. Звичайний прогноз погоди
каже «хмарно», але не каже, скільки кіловат-годин дасть саме ця станція з її
потужністю, нахилом та орієнтацією.

Користувач задає населений пункт, потужність панелей, нахил, орієнтацію, ємність
акумулятора і тариф. Сервіс повертає:

- вироблення на кожен із семи днів і по годинах;
- три найсильніші години поспіль кожного дня;
- чи зарядиться акумулятор повністю і о котрій;
- економію за тарифом;
- план на тиждень простими словами, який складає модель Claude.

![Головний екран: параметри станції, підсумок за сім днів, вироблення по днях і крива вибраного дня](docs/main-top.png){width=92%}

**Де це застосовне.** Домогосподарства з власною генерацією під час відключень;
ОСББ і невеликі бізнеси з панелями на даху; монтажники, які хочуть показати клієнту
очікуваний виробіток ще до встановлення; системи «розумного дому», які вмикають
навантаження за розкладом через REST API сервісу.

# 2. Які API використовуються

Важку обчислювальну роботу виконують готові хмарні сервіси. Власний код лише
поєднує їхні відповіді та рахує потужність станції.

## Зовнішні API

| API | Призначення | Доступ |
|:-----------------------|:-----------------------------------------------|:-------------|
| Open-Meteo Geocoding API | Знаходить координати і часовий пояс за назвою населеного пункту українською | без ключа |
| Open-Meteo Forecast API | Погодинна сонячна радіація на площину панелі (`global_tilted_irradiance` з параметрами `tilt` і `azimuth`), температура, хмарність, схід і захід сонця | без ключа |
| Claude API, Messages (модель `claude-opus-5-5`) | Складає план на тиждень природною мовою у структурованому вигляді | ключ на сервері |

Відповідь моделі не є вільним текстом. Разом із запитом передається схема
(Pydantic-модель `Advice`: заголовок, підсумок, порада на кожен день, план приладів,
застереження), і API повертає відповідь саме такої структури. Тому інтерфейс не
розбирає довільний текст. Для випадків, коли модель відхиляє запит, увімкнено
серверний резервний маршрут Claude API.

## Власний REST API

| Метод | Призначення |
|:------------------------|:---------------------------------------------------------|
| `GET /api/geocode` | пошук населеного пункту |
| `GET /api/forecast` | прогноз вироблення: по годинах, по днях, підсумки |
| `POST /api/advice` | план на тиждень: Claude або запасні правила |
| `GET /api/health` | стан сервісу і кешу |

Документація OpenAPI генерується автоматично і доступна за адресою `/docs`.

## Як рахується вироблення

Open-Meteo повертає радіацію вже перерахованою на нахил та орієнтацію панелей.
Сервіс переводить її в потужність за стандартною оцінкою для невеликих станцій:

`P = Pпік × GTI / 1000 × (1 − втрати) × (1 − 0,004 × (Tел − 25))`

Тут `Pпік` — паспортна потужність панелей у кВт, `GTI` — радіація на площину панелі
у Вт/м², втрати (інвертор, кабелі, пил) за замовчуванням 14%, `Tел` — температура
елемента: гарячий елемент дає на 0,4% менше на кожен градус понад 25 °C. Сума 24
годинних значень дає кВт·год за день.

# 3. Взаємодія між сервісами

![Схема взаємодії сервісів](docs/architecture.png){width=100%}

1. **Пошук місця.** Браузер викликає `GET /api/geocode`, сервіс звертається до
   Open-Meteo Geocoding API і повертає список населених пунктів з координатами.
2. **Прогноз.** Браузер викликає `GET /api/forecast` з параметрами станції. Сервіс
   бере погодинну радіацію в Open-Meteo Forecast API, рахує потужність за моделлю і
   повертає дані по годинах, по днях та підсумки. Відповіді Open-Meteo кешуються на
   15 хвилин.
3. **План на тиждень.** Браузер викликає `POST /api/advice` з тими самими параметрами
   станції. Сервіс сам перераховує прогноз і надсилає підсумки по днях у Claude API
   разом зі схемою відповіді. Модель отримує лише числа, які порахував сервіс, а не
   дані від клієнта.
4. **Запасний шлях.** Якщо Claude недоступний (немає ключа, вичерпано ліміт, зникла
   мережа, модель відмовила) або відвідувач не має коду доступу, ту саму структуру
   заповнюють детерміновані правила. Інтерфейс показує, хто склав план.

Ключ Claude API зберігається лише на сервері: браузер звертається тільки до власного
API сервісу.

# 4. Розгортання в хмарі

Сервіс розгорнуто на віртуальній машині Hetzner Cloud (CX23: 2 vCPU, 4 ГБ, Гельсінкі,
Ubuntu 26.04) і доступний за адресою **https://solarcast.trelawney.tech**.

- Два контейнери в Docker Compose: застосунок (FastAPI) і Caddy. Caddy приймає
  з'єднання з інтернету, сам отримує сертифікат Let's Encrypt і проксіює запити.
- Застосунок з інтернету напряму недоступний, працює без привілеїв і з файловою
  системою лише для читання.
- На сервері ввімкнено фаєрвол (порти 22, 80, 443) та автоматичні оновлення безпеки.
- Розгортання виконує одна команда: `./deploy/deploy.sh <ssh-хост> <домен>`.
- DNS: A-запис `solarcast.trelawney.tech` вказує на адресу віртуальної машини.

Оскільки кожен план від Claude коштує близько 5 центів, платну модель на публічній
адресі захищено: код доступу, шість запитів плану за 10 хвилин з однієї адреси, денна
стеля викликів моделі на сервіс і на одного клієнта. Без коду сайт і прогноз працюють
повністю, а план складають безкоштовні правила.

У цьому прикладі модель сама помітила, що бойлер на 2 кВт станція потягне лише у два

близько 20 секунд і використовує приблизно 4 тис. вхідних та 1,4 тис. вихідних токенів.

Якість коду підтверджують 36 автоматичних тестів: модель вироблення, власний API,
ліміти та код доступу. Зовнішні API в тестах підмінені, тому тести не потребують
мережі й нічого не коштують.

# Висновки

У проєкті поєднано три хмарні API: два відкриті API Open-Meteo дають місце і сонячну
радіацію, а Claude API перетворює числа прогнозу на зрозумілий план дій. Власний
сервіс рахує потужність станції, кешує відповіді, обмежує витрати на модель і працює
навіть тоді, коли модель недоступна. Сервіс розгорнуто в хмарі на віртуальній машині
Hetzner Cloud з автоматичним HTTPS.
